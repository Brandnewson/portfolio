## Knowledge entries (src/content/knowledge/)

### Frontmatter schema

```typescript
const knowledgeCollection = defineCollection({
  type: 'content',
  schema: z.object({
    title: z.string(),               // Display name e.g. "Aerodynamics"
    tags: z.array(z.string()),       // For vocabulary/synonym lookup e.g. ["aerodynamics", "drag", "downforce"]
    domain: z.enum([                 // Broad category for filtering
      'engineering',
      'software',
      'ai-ml',
      'gtm',
      'motorsport',
      'research'
    ]),
    source: z.string(),              // Where this was learnt e.g. "Jaguar Land Rover — Formula E placement"
    date: z.string().optional(),     // Approximate period e.g. "2023"
  })
})
```

### Example file (src/content/knowledge/aerodynamics.md)

```markdown
---
title: Aerodynamics
tags: [aerodynamics, drag, downforce, aero, CFD, Formula E, peloton]
domain: motorsport
source: Jaguar Land Rover — Formula E placement
date: "2023"
---

During the Jaguar Land Rover Formula E placement, Branson worked on
drag penalty analysis and energy save strategies for peloton-style
racing. Formula E's street circuits and energy limits make aerodynamic
efficiency a first-order concern — unlike Formula 1 where raw downforce
dominates, Formula E requires balancing drag reduction with energy
recovery, particularly in the slipstream dynamics of close racing.

This led to an understanding of how aerodynamic surfaces interact with
race strategy: the decision to drop back slightly (increasing drag but
recovering energy) versus pushing hard (burning energy for position).
```

## Tech notes (src/content/tech-notes/)

### Frontmatter schema

```typescript
const techNotesCollection = defineCollection({
  type: 'content',
  schema: z.object({
    title: z.string(),               // Short label e.g. "Search pipeline"
    element: z.string(),             // Which UI element this explains e.g. "SearchWidget"
    tags: z.array(z.string()),       // For cross-linking with knowledge entries
    difficulty: z.enum(['concept', 'implementation', 'decision']).optional()
  })
})
```

### Example file (src/content/tech-notes/search-pipeline.md)

```markdown
---
title: Four-layer search pipeline
element: SearchWidget
tags: [information retrieval, embeddings, fuzzy search, semantic search]
difficulty: implementation
---

The search widget runs four layers in sequence, each catching
what the previous misses.

**Levenshtein distance** handles typos — if your query is within
edit distance 2 of a vocabulary term, it surfaces "Did you mean?".
This is a custom 15-line implementation, no library needed.

**Synonym expansion** handles domain adjacency — Docker expands to
CI/CD because they're linked in synonyms.json. This is manually
curated, which means Branson decided those connections, not an
algorithm.

**Fuse.js** handles fuzzy string matching against the full body
text of knowledge entries. It catches partial matches and
misspelled terms that survive the Levenshtein check.

**Pre-computed embeddings** handle genuine semantic similarity —
cases where the words don't match but the meaning does.
Embeddings were generated at build time using OpenAI's
text-embedding-3-small model. Runtime inference runs via a
small ONNX model in the browser (Transformers.js), so no API
call happens during your search.

This comes directly from the Information Retrieval module
(COMP3011) — inverted indices, ranking functions, and query
processing, applied to a real use case.
```

## Lookup table (src/data/lookup_table.json)

Auto-generated by scripts/generate-lookup.py. Never edit manually.

type LookupTable = LookupEntry[]
